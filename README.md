# يَومي — مشروع قابل للنقل

تطبيق شخصي لتنظيم يومك ومهامك وتعلّمك وعبادتك. الواجهة العامة شبابية وعملية، والعبادات موجودة داخل تبويبها الخاص. تبويب «اكتشف» فيه مكتبة من ١٠ فيديوهات مباشرة؛ يعرض ٥ يوميًا، بينها محتوى ديني وتاريخي، والباقي مهارات وتطوير شخصي.

## التشغيل

- افتح `index.html` في متصفح حديث. لا يحتاج المشروع إلى تثبيت أو اشتراك.
- تذكيرات مواقيت الصلاة ومحتوى الإنترنت تحتاج اتصالًا بالإنترنت.
- أضفت إعدادات تثبيت كتطبيق (PWA). ارفع مجلد المشروع على استضافة HTTPS، ثم افتحه من متصفح الهاتف واختر «إضافة إلى الشاشة الرئيسية». ملفات التطبيق الأساسية تُخزّن للعمل دون اتصال؛ مواقيت الصلاة والمحتوى الخارجي يحتاجان إنترنت.

## فتحه كتطبيق على الموبايل

ملف ZIP وحده لا يثبّت التطبيق على الهاتف؛ لازم يتوفر له رابط HTTPS. أسهل طريقة مجانية هي GitHub Pages:

1. أنشئ مستودعًا جديدًا على GitHub وارفع ملفات مجلد `yawmi` نفسها (ومنها `index.html`) إلى الجذر.
2. من إعدادات المستودع افتح Pages، واختر النشر من الفرع `main` ومجلد الجذر. بعد اكتمال النشر سيظهر رابط HTTPS للموقع. دليل GitHub Pages الرسمي: https://docs.github.com/en/pages/quickstart.
3. افتح الرابط على الموبايل. على iPhone استخدم Safari ثم «مشاركة» ← «إضافة إلى الشاشة الرئيسية» وفعّل «فتح كتطبيق ويب» (https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236). على Android افتحه في Chrome ثم من القائمة اختر «تثبيت التطبيق» (https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=en-2).
4. بيانات التطبيق تفضل محفوظة على نفس الجهاز والمتصفح. لن تتزامن تلقائيًا بين الكمبيوتر والموبايل؛ صدّر JSON من زر السهم في الجهاز الأول واستورده في الثاني. احتفظ بنسخة JSON الخاصة بك خارج المستودع ولا ترفعها إلى GitHub.

## إعداد Supabase للمطوّر وتسجيل دخول المستخدم

المستخدم العادي يرى شاشة تسجيل الدخول وتبويب «إعدادات» فقط؛ حقول Project URL والمفتاح غير ظاهرة له. إعداد الربط مرة واحدة مسؤولية المطوّر في الملف `supabase/config.js`.

1. أنشئ مشروع Supabase، ثم افتح SQL Editor وشغّل محتوى `supabase/schema.sql`.
2. من Connect أو Settings → API Keys انسخ Project URL وPublishable key (أو anon public key). لا تستخدم secret أو service_role key.
3. ضع القيمتين في `supabase/config.js` داخل `url` و`publishableKey`. المفتاح العام مصمم للاستخدام في التطبيق، وسياسة RLS تحصر كل صف في صاحبه.
4. انشر مجلد المشروع على HTTPS. في Supabase Authentication → URL Configuration اضبط Site URL على رابط التطبيق.
5. افتح رابط التطبيق واضغط أيقونة الحساب، ثم سجّل الدخول أو أنشئ حسابًا. على أجهزتك الأخرى افتح نفس رابط التطبيق وسجّل الدخول بالحساب نفسه.

تُرفع بيانات يَومي بعد التعديلات تلقائيًا، ويظهر خيار عند اختلاف تغييرات الجهاز والسحابة. تفاصيل النسخ الاحتياطي اليدوي موجودة في تبويب الإعدادات. لا ترفع ملف بياناتك الخاص إلى مستودع عام.

## بياناتك ونقلها

التطبيق يحفظ بياناته محليًا في المتصفح الحالي. من زر السهم أعلى الصفحة اختر «نزّل نسخة بياناتي JSON». احتفظ بملف النسخة داخل مجلد `data/` بجانب المشروع. على جهاز أو متصفح آخر افتح المشروع ثم استعد نفس الملف من زر السهم. النقل بين الحسابات يتم بملف النسخة، أما ملفات المشروع وحدها فلا تحتوي تلقائيًا بيانات المتصفح.

ملف `data/schema.json` يشرح مفاتيح البيانات، و`data/backup.example.json` قالب فارغ فقط. لا ترفع نسخة بياناتك الشخصية للعامة؛ قد تتضمن ملاحظات وسجل عبادتك.

## تطويره بمساعدة Claude أو أي محرر

أرسل مجلد المشروع للمساعد، واطلب منه تعديل `index.html` أو `styles.css` أو `app.js`. احتفظ بنسخة JSON منفصلة قبل أي تعديل كبير، ثم اختبر الاستعادة على نسخة من المشروع. النسخة الحالية تعمل دون خادم مدفوع؛ المساعد الداخلي يعتمد قواعد محلية ولا يرسل بياناتك إلى خدمة ذكاء اصطناعي.

## محتويات المجلد

- `index.html`: بنية التطبيق.
- `styles.css`: التصميم.
- `app.js`: التفاعلات والتخزين المحلي.
- `data/`: قالب النسخة وشرح صيغة البيانات.
